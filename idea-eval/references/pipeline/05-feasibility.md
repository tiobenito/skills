# Stage 5: Feasibility

The team is highly technical and AI-native. They can build anything with modern AI-assisted development tools. Assume no technical skill gaps.

**The question is NOT "can they code this?"** The answer is almost always yes.

The real question is: what are the NON-TECHNICAL blockers?

## Output Fields

- **tech_sketch**: High-level architecture (2-3 sentences), key integrations, and genuinely hard technical problems (not "learning React" — think "real-time audio processing" or "offline-first sync"). Say "None" if straightforward.
- **complexity**: Level (low/medium/high) with reasoning
- **side_project_feasible**: Verdict (yes/yes_but/no) with explanation. Can this realistically be built and operated at 4-8 hrs/week?
- **real_blockers**: Non-technical barriers (enterprise sales cycle, regulatory approval, large content library needed, etc.) with severity and workarounds
- **cost_to_operate**: Monthly estimate at modest scale with breakdown
- **key_risks**: Execution and business risks with mitigation strategies and severity

## Rules

1. Do NOT list specific tools, frameworks, or languages — keep it architectural
2. Focus real_blockers on things that AREN'T about building software
3. Be honest about whether something is a side project or secretly a full-time startup
4. Do NOT include time estimates — the team will determine their own pace
5. If there are no hard technical problems, say so — don't manufacture complexity
